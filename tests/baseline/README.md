# Numerical baselines for the legacy EDRegisterSparse_Show_iter_* scripts

Captured from the unmodified-numerics scripts in the repo root so that a refactor can be regression-checked.
Deterministic: repeated runs gave bit-identical error histories and P0 (checked for lm_v2, cg, pcg, gauss_newton, gauss_newton_fd).

## Environment
- MATLAB R2026b (Apple Silicon, macOS), toolboxes: Computer Vision, Image Processing, Optimization, Parallel Computing, PDE.
- Data: simple_poisson_mesh_020.ply (source, 5027 verts) -> simple_poisson_mesh_022.ply (target, 5033 verts), `rng(1,'twister')` set right after reading the plys (this is what the scripts do; Jall_FINAL was switched to the same ply+rng lines).
  (In the ED_Jacobian repository the plys had been renamed to data/human_020_f10k.ply and data/human_022_f10k.ply; SHA1 020=81475f9c..., 022=15c0a6a9...)
- Each script run on its own: `matlab -batch "addpath('shims'); run_<solver>"`, cwd containing the plys and the `+jwutils` package.

## Shims (shims/) - no GPU / Statistics Toolbox / mexopencv on the capture machine
- `bl_gpuArray.m`: identity. The built-in `gpuArray` cannot be shadowed by a path function, so the patched scripts call `bl_gpuArray` (textual rename of every `gpuArray(`).
- `knnsearch.m`: only `'K',1`, Euclidean, ties -> lowest index. Checked against brute force: 0 mismatches.
- `+cv/Rodrigues.m`: rotation vector -> R and 3x9 Jacobian (row i = dR/dr_i, row-major R). Series expansion for |r|<0.05, so r=0 gives the skew-matrix derivative. Checked vs central finite differences (h=1e-6) at 56 vectors incl. r=0 and |r|~1e-6: max abs error 3.6e-10 (FD round-off level); R orthogonal to 8e-16.
- `test_rodrigues.m`: the check above.

## Patches (see patched_scripts/, generated by patch.py; all marked `%BASELINE`)
Numerics (iteration counts, weights, lambda rules, solvers) untouched. Changes:
1. `global BL_ERR BL_LAM BL_LAMOUT BL_ELAPSED BL_INIT` initialised after line 1; declared in runOptim.
2. Per iteration, right after the existing `fprintf("Iter ...")`: `BL_ERR(end+1)=sum(F.^2)` (plus `BL_LAM` = printed lambda, `BL_LAMOUT` = lambda after the update, in lambda-based scripts) and a `%.15g` print.
3. `toc;` in runOptim -> `BL_ELAPSED = toc;`.
4. `show_iteration=false; show_final=false` (only avoids pause(1)+figures; PCG already had show_iteration=false).
5. Save block inserted before the first local function: saves `<solver>.mat`.
6. Jall_FINAL (lsqnonlin): ply+rng lines uncommented, `load(fullfile(DIR,...))` lines commented; `outfun` appends `optimValues.resnorm` at state 'iter' to BL_ERR and stores the 'init' resnorm in BL_INIT; `tic`/`BL_ELAPSED = toc` around lsqnonlin.
7. Files were rewritten with LF line endings (originals CRLF).

## .mat contents
`BL_ERR` (per-iteration sum(F.^2) as printed by the script, i.e. error at the start of the iteration for gradient/GN; for lsqnonlin the resnorm at each 'iter' call), `BL_LAM`/`BL_LAMOUT` (lambda scripts), `BL_INIT` (lsqnonlin initial resnorm), `BL_ELAPSED` (s, machine dependent), `BL_iters`, `BL_matlab`, `BL_P0` (final), `BL_deformedV` (final, 5027x3), `BL_nodeIdx`.
Note for lm_v2/cg/pcg: the iteration on which `lambda > 100000` triggers `break` is not recorded in BL_ERR.
